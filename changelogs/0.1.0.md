# 0.1.0 — 2026-05-07

Initial release of the Claude Code Project Manager template. Modular architecture, two changelog templates, a default version-control template, guided/defaults setup, and a post-setup workflow briefing.

## API

| Tag | Change |
|---:|---|
| ![feature] | <details open><summary>Module manifest at `manifest.json`</summary><br>Consumer projects fetch `https://raw.githubusercontent.com/KROIA/ClaudeCodeTemplate/main/manifest.json` once during init.<br><br>Adding a new module = drop a folder + append one entry. Adding a new variant of an existing module = drop a file + append to that module's `variants` array. No spec edits required for variant additions.</details> |
| ![feature] | `schema_version: 1` declared in `manifest.json` for forward compatibility |

## CLI

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Guided vs. defaults setup mode</summary><br>First question of init asks "Guided or defaults?". Guided mode runs ~8 batched questions upfront; defaults mode skips all questions and uses a deterministic defaults table (review gate off, commit/push permission `none`, testing skipped, branches on current).</details> |
| ![feature] | Custom file option for every module — user can supply an absolute path to a local markdown file instead of a manifest variant |
| ![feature] | <details><summary>Five-phase init flow</summary><br>(A) ask upfront → (B) execute unattended → (C) workflow review + free-form additions → (D) self-overwrite → (E) post-setup briefing.<br><br>The user is interrupted only in phases A, C, D, E. Phase B runs straight through.</details> |
| ![feature] | Free-form preferences capture in §2.5 — name, address, workflow overrides, team conventions, notes |
| ![feature] | Post-setup briefing (§2.7) hands off to the working loop: code review → `ISSUES.md` → user review → process to tasks → execute → release |

## Documentation

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>`ChangelogTemplates/Default.md` — sectioned tables with badge tags</summary><br>Per-version files with closed-set top-level sections (Security, Performance, API, CLI, UI/UX, Build & Dependencies, Documentation, Internal) and a closed-set tag vocabulary (`![feature]`, `![improvement]`, `![bugfix]`, `![breaking]`, `![removal]`, `![deprecation]`, `![hardening]`).<br><br>Right-aligned tag column, shields.io badges via reference-style links, optional `<details>` blocks for collapsible entries.</details> |
| ![feature] | <details><summary>`ChangelogTemplates/Minimal.md` — plain markdown, drop empty sections</summary><br>Headings + bullet lists only. No tables, no badges, no HTML. Section vocabulary: Features, Improvements, Bugfixes, Breaking changes, Deprecations, Removals, Security, Documentation, Internal.<br><br>PM is required to **filter out any section with zero entries** before writing — no empty headings, no "None" placeholders.</details> |
| ![feature] | <details><summary>`VersionControlTemplates/Default.md` — git-flavored conventions</summary><br>Commit message format with single-char type prefix (`+ ~ - ! *`), branch naming (`feat/`, `fix/`, `chore/`, `refactor/`, `docs/`, `release/`, `hotfix/`), squash-merge default, repo artifact policy table, release & hotfix flows, SVN notes inline.</details> |
| ![improvement] | German install instructions in `readme.md` flag that init requires internet access for manifest + variant fetches |

## Build & Dependencies

| Tag | Change |
|---:|---|
| ![feature] | <details><summary>Project Manager spec at `ClaudeProjectManagerSetup/CLAUDE.md`</summary><br>Canonical setup spec — copied into consumer projects, auto-loaded by Claude Code on session start, self-overwritten to a lean runtime briefing (§10) after init succeeds.<br><br>Defines task/issue schema with hotfix lane, Definition of Done stage checklist, priority rubric, two-tier VCS permissions (commit / push), pre-commit ritual, conflict resolution, secrets policy.</details> |
| ![feature] | Subagent template requirements — every subagent declares an **agent contract**: Inputs, Outputs, Files/paths it may touch, Model |
| ![feature] | Harness hook wiring during init via the `update-config` skill — session start auto-load, pre-commit ritual, secret-file write blocks, DoD enforcement, VCS permission gating |

| Tag | Change |

| ![improvement] | Defaults table (§2.3) makes defaults mode fully deterministic — same inputs always yield the same `PREFERENCES.md` |
